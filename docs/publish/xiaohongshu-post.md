# 小红书发布文案（短笔记）

笔记标题（20 字内）：**AI 写代码后，工作区谁来收拾？**

## 正文（直接粘贴）

AI 写代码越来越快，工作区也越来越乱🌪️

草稿、缓存、废弃方案堆得比代码还快，下一轮 AI 还要在垃圾堆里干活。

我开源了一个小工具，把工作区当成「活的系统」来管理：

🗑️ 检查：只体检不下手，给文件贴标签
♻️ 回收：过期文件移进回收区，绝不直接删
🔒 验证：每次移动都有防篡改记录
↩️ 回滚：发现删错了？一键还原

核心思路：一份策略文件说了算，工具只做策略允许的事，默认只读、不会误删。

我把这个框架叫作「智能体代谢工程」——agentic 工程栈的 L5 层：每一轮 AI 循环结束后，留下的副产物怎么办。

诚实说明：这是提出一种框架，不宣称造词。工具零依赖，Windows / Mac / Linux 都能用，已经在 GitHub 开源。

GitHub 搜索：workspace-metabolism
