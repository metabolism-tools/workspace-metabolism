## 优先候选

### 1. Claude Code 临时文件问题

- 公开线索：[anthropics/claude-code#8856](https://github.com/anthropics/claude-code/issues/8856)
- 公开作者：`Sundeepg98`
- 匹配证据：Issue 描述 Claude Code 在 `/tmp` 下持续留下 `claude-*-cwd` 文件，作者报告一天积累 174 个文件，并给出了复现、隐私和磁盘累积影响。
- 适合验证的问题：用户是否需要“先审计、再清理、可回滚、保留审计记录”，而不是只要一条删除命令。
- 推荐触达方式：在原 Issue 下说明这是一个独立的、可回滚的外部试用方案，邀请作者用一个临时目录跑 demo；不要宣称项目已经解决 Claude Code 的缺陷。
- 风险：Issue 已有较多讨论，先阅读最新评论，避免重复建议或把外部工具包装成官方修复。

### 2. OpenClaw 工作区残留目录问题

- 公开线索：[openclaw/openclaw#104358](https://github.com/openclaw/openclaw/issues/104358)
- 公开作者：`danilovmy`
- 匹配证据：Issue 描述 `media/inbound/openclaw-staged-*` 空目录持续积累，并明确指出外部定时清理只是当前 workaround。
- 适合验证的问题：对带有生命周期规则、保留期限、来源标记和回滚能力的治理工具是否有兴趣。
- 推荐触达方式：先在 Issue 中承认该项目已有多个修复 PR，再询问是否愿意用 `workspace-metabolism` 做一次只读审计对照；不要直接提交宣传评论。
- 风险：该 Issue 已有自动审查机器人和多个修复方向，不能把它当成没有解决方案的空白需求。

## 第一轮建议

只触达前两个公开 Issue，采用一对一、问题导向的短消息。目标不是获取 Star，而是验证：

1. 他们是否愿意在临时目录运行 `python examples/demo.py`。
2. `audit` 报告里的候选、保留期限和回滚证据是否能帮助他们判断。
3. 他们更需要一次性清理、定时治理，还是集成到现有 Agent 工作流。

建议记录：公开线索链接、触达日期、是否回复、是否试用、实际问题、下一步。记录应放在私有表格或本地文件，不提交到公开仓库。
