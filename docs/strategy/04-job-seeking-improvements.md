# 求职导向改进提案（2026-09-02 讨论存档 4/4）

> 来源：外部提案原文存档。视角：**求职（面试叙事）优先**——与 02 的产品冷启动视角互补/部分冲突。
> 前提：该提案确认批判性分析中的风险点"全部真实存在"，并主张分层处理（应该做/不该做/建议不做）。

## 一、应该做的改进（跟求职直接相关）

### 1. wm gate：增加醒目的实验性警告 ⭐（1小时）
- 在 `wm gate` 启动时终端输出醒目警告（ANSI 颜色/加粗）：实验性功能，不提供真正的身份验证或强制拦截
- 边界声明移到 `wm gate --help` 第一屏
- 原因：面试被问安全边界时，"主动做了醒目实验性标记"比"这是实验性的"更有说服力——体现批判性认知与防误用意识

### 2. 边界声明前置 ⭐（30分钟）
- 把 README "what this is not" 移到副标题之后，醒目格式（引用/警告块）
- 核心要点：不是沙箱（恶意Agent可绕过）；不是启发式分类器；不能修复Agent本身的bug；不替代Agent自我清理
- 原因：面试官快速浏览 README 时第一眼看到边界声明 → "工程严谨性"评估上台阶

### 3. holdout-labs 高层封装 ⭐（1-2天）
- holdout-governance 增加高层 API，例如：
```python
from holdout_governance import audit_pipeline
report = audit_pipeline(data_dir="./my_workspace")
# 输出一个PDF/HTML报告，包含所有检查结果
```
- 原因：招聘方看到"高层封装"= 有产品化能力（系统设计环节加分）

### 4. 测试场景补充 ⭐（1-2天）
- 符号链接和WSL混合环境测试用例
- 停牌、涨跌停等A股边缘场景测试用例
- 并发测试（外部进程同时修改文件时工具的检测能力）
- 大目录扫描性能测试
- 原因：简历可写"**94个测试全绿，覆盖符号链接、网络挂载盘、停牌/涨跌停等边缘场景**"

## 二、不应该现在做的改进（求职阶段不需要）

### 5. policy schema兼容层（不建议现在做）
- 无用户之前不做企业级迁移工具；被问到时说"已标记实验性，v1.0前提供迁移工具"即可

### 6. 强制MCP代理模式（不建议现在做）
- 真正强制需 OS 层拦截（LD_PRELOAD/eBPF/seccomp），系统工程；无真实用户反馈不知道要拦什么

### 7. 策略建议能力/智能辅助（不建议现在做）
- 理由（原文）：本质是"启发式分类器"，与"不是启发式分类器"的定位自相矛盾，让工具定位模糊

## 三、建议不要做的改动（对求职是负资产）

### 8. wm gate 实验性标记但不当核心亮点（建议做，不作求职核心卖点）
- 主动承认局限优于面试官自己发现；作为"未来方向"讲，不作为"现在亮点"

### 9. 删除README中"没有外部用户"的声明（建议立即做）
- 理由（原文）：求职时会被面试官直接看到，产生疑虑；"用户数可以等入职后再慢慢积累"

### 10. 降低holdout-labs入门门槛（建议做，但不作为核心亮点）
- 提供从原始数据到输出审计报告的**完整端到端示例**（可用模拟数据），放 examples/，5分钟跑通
- 比写文档更有说服力；不花时间在UI/可视化上
