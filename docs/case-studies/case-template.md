# 案例：<可验证的问题>

- 案例编号、日期、更新记录：
- 范围：wm 直接行为 / 相关系统经验 / 尚待检验的假设。
- 状态：观察到 / 隔离复现 / 已修复 / 已部署 / 下游已验收 / 长期效果待观察。
- 触发与影响：包括正常完成、失败、复发或没有收益。
- 任务边界：输入、消费者、风险、允许自动做什么、何时交给人。
- 原有流程与比较条件：同类任务量、时间窗口、同期改动。
- 原始证据引用：位置、版本、时间、覆盖范围、校验值；公开版移除私有位置。
- 采取的动作：包括未成功的尝试、重试、恢复与人工接管。
- 验收证据：测试通过、发布生效、下游恢复分别记录；缺失或空样本填未知。
- 人工监督：次数 / 分钟 / 计量来源；人的决策与创造另记。
- 结果与代价：有效任务数、失败数、复发、存储净变化、计算与 Token、备份和恢复成本；未计量填未测。
- 反例与局限：潜在漏报、其他解释、不可外推的范围。
- 可复用的机制：已有技术是什么，新增差异是什么。
- 价值假设：独特性、学术问题、客户痛点分别列出支持证据与缺口。
- 下一次验证：用什么观察推翻或支持假设；何时停止无收益尝试。
- 数据维护：复用哪个回执、保留期限/保护级别、容量预算、清理边界。
- 发布检查：脱敏完成？有合成复现？尚未验证的主张标清？
