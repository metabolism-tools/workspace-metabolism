# AI治理即代码：一次从存储维护走向研究工作流验收的工程实践

> 成文：2026-09-09。案例事实窗口：2026-09-08，Asia/Shanghai。
> 真实个人交易系统的研究维护案例，已脱敏。生产维护、隔离测试与待验证目标分别陈述；不据此推断交易收益或整体系统安全。

一次维护释放了66.43 GB空间，却没有被评价器判为完整闭环成功。原因很具体：数据还原与完整性已有证据，但下一段真实研究工作的消费验收尚未补齐。

这正是本案例中“AI治理即代码”的含义：**将允许做什么、必须保留什么、用什么证据验收、何时保持未完成，落实为可检查的规则、程序和回执。** AI可以参与诊断和工程实现；确定的边界与检查由程序重复执行，人负责目标、后果取舍和权限变化。

这里的治理对象是AI参与的研究维护与工作流交接，不是模型对齐、内容安全或企业合规的完整治理体系。它也是一项渐进实践：部分执行保护已在线运行，评价器仍为只读工具，完整自动治理闭环尚未完成。

## 为什么个人系统需要这层治理

研究程序在非交易时间不断生成数据、检查点和历史结果。数据积累可以支持后续研究，也会增加存储、读取和维护负担。个人系统没有专门团队持续检查每一个维护动作，因此目标不能停在“让程序自动多做一些事”。

最初讨论AI数字劳动的文章给了我们一个有用问题：完成工作需要多少人工监督？本案例把它进一步收窄为：

> 保留哪些证据、设置哪些隔离和恢复条件，才能让维护更少需要人接管，同时不损害下游工作的正确性？

人工监督包括反复查日志、确认结果、催办和纠错；选择研究目标、改变风险容忍度则属于决策。减少前者可以独立成为成果，不要求同时省Token，也不要求无人干预时间越长越好。错误后果越大，对证据、隔离、恢复和人的决策要求就应越严格。

## 与“到点执行清理”相比，多管了什么

定时器解决何时启动。它可以承载下面全部机制；差异来自任务的治理要求，而不是有没有cron，也不是有没有调用大模型。

| 维度 | 仅按时间或容量执行清理 | 本案例的治理实践 |
|---|---|---|
| 目标 | 删除到期内容、腾出空间 | 降低维护负担，同时保留后续判断所需证据 |
| 动作边界 | 按路径、日期或大小选择对象 | 结合实际消费者，保护必要字段与共享引用；不确定时不扩大删除 |
| 执行验收 | 命令退出成功、空间下降 | 分别检查执行、内容完整性、真实消费与必要恢复 |
| 证据关联 | 有一份成功日志 | 同一任务、范围、版本、输入内容和有效时间必须对得上 |
| 异常处理 | 失败后重试或告警 | 区分执行失败、证据不足、用途变化和需要人决策；旧问题不被静默关闭 |
| 衡量收益 | 删除数量、回收字节 | 先核对下游正确性，再比较同类任务的人工监督与总成本 |

成熟维护系统也可以具备这些能力。本案例不声称上述机制独创；价值在于把它们落实到一个真实、资源有限的系统，并让“少监督”的主张接受证据检验。

## 第一处转变：按下游需要决定保留边界

早期维护曾依赖“旧研究批次结束后，部分详细字段不再需要”的判断。后续检查实际消费者，发现其中一些证据仍可能用于判断与投影，原结论缺乏足够依据。

处理结果是修正历史案例表述，保护必要字段，并保持自动删字段关闭。生产wm升级到0.5.2，观察入口不执行自动瘦身。

这不是一次成功清理的附注，而是治理中的纠错：**维护权限应服从已知下游依赖，不能用回收量证明删除合理。** 配置可修改不等于可以无证据扩大权限。完整性、业务恢复和长期可靠性也不能被合并成一个可由空间收益抵消的总分。

## 第二处转变：把不可证实的删除换成可核验的无损维护

本次选定279份研究矩阵，由业务系统的领域工具执行共享存储迁移：重复内容存为共享压缩块，原文件保留引用。它与wm的保护政策、维护流程协作；这不是wm通用命令独自完成的全部功能。

每份替换前都通过真实读取函数还原内容，并与原始序列化字节比较；确认源文件未发生变化，记录迁移意图，再原子替换。完成后另做全范围引用及共享块校验。

| 生产实测 | 结果 |
|---|---:|
| 迁移对象 | 279份矩阵 |
| 共享内容块 | 60个 |
| 目录迁移前，含既有共享内容 | 67,849,958,357字节 |
| 目录迁移后，含共享内容 | 1,416,146,145字节 |
| 净减少 | 66,433,812,212字节，约66.43 GB |

这证明了限定范围内的无损维护与存储收益。279份文件属于同一个维护机会，不是279次独立事故，也不是279份低监督成功样本。共享内容仍受保护，不能随后当作普通缓存清理。

## 第三处转变：程序可以报告“维护做完了，但验收没做完”

公开的只读评价器将任务、对象范围、策略版本、执行器版本和消费者版本绑定起来。缺少检查、证据过期、对象错配、重复声明，均不能得到全部声明检查通过的结果；明确失败另行保留。

消费者检查还要求真实工作流、预期与实际输入清单一致、成果摘要、约定的领域验收规则及有效时间。心跳正常、读取抽查和回放不能替代下一段真实工作的验收。

用本案例的[脱敏证据包](evidence/matrix-maintenance-20260908.json)可以复现：

```sh
python tools/evaluate_maintenance_cycle.py docs/case-studies/evidence/matrix-maintenance-20260908.json --as-of 2026-09-08T13:27:42.785578+00:00
```

关键输出为：

```json
{
  "state": "verification_pending",
  "checks_passed": ["integrity"],
  "gaps": ["consumer:missing"],
  "supervision_benefit": "not_established",
  "authorizes_execution": false
}
```

这是按原核验时点回顾性整理的案例，不是事前注册的对照实验。不能为得到通过状态而更新旧证据的时间。

评价器核对的是声明关联，尚不认证来源、不独立验证业务结果，也不充当生产执行门禁。其`declared_checks_passed`只表示声明检查通过；伪造JSON不能靠它识别。这项限制属于案例的事实，而不是可以省略的实现细节。

## 第四处转变：让真实工作顺便留下治理证据

只要求“以后补回执”，仍可能把监督工作留给人。因此，我们在私有研究系统的工作进程前后接入记录入口，将输入内容指纹、请求、结果指纹和代码文件指纹放入原有台账。

这里又发现一个容易遗漏的问题：若对完整内存返回值计算指纹，但台账只保存其中部分字段，事后就无法独立复查。最终实现对**实际保留的结果投影**计算指纹，成功和返回拒绝两条路径均可从测试数据库重算一致。原研究计算的完整返回结果在合成输入对照中保持一致。

记录采用固定工作单元抽样，设置计算预算，超限返回证据缺失，不留下貌似完整的部分摘要；不另建无限增长的日志库。观察状态固定为`observed_not_accepted`，不能自动换成业务验收通过。抛异常仍沿原失败路径处理，缺少完成回执不算成功。

截至本案例证据窗口，接入代码已提交，最终补丁33项相关测试通过；生产发布与后续真实研究消费尚未在本案例核验。固定抽样不代表历史279份矩阵的全范围消费，也不证明人工监督已下降。

## 治理规则落到了哪里

| 规则 | 工程载体 | 本案例状态 |
|---|---|---|
| 必要证据不能随意删除 | wm策略及领域维护边界 | 已应用；自动删字段关闭 |
| 内容必须可还原、可追溯 | 领域迁移工具、原回执、全范围校验 | 已在限定生产范围验证 |
| 不能挪用其他任务或过期检查 | [维护循环评价器](../../tools/evaluate_maintenance_cycle.py)及[测试](../../tests/test_maintenance_cycle.py) | 公开、只读、核对声明 |
| 实际使用与观察成功分开 | 私有消费者记录入口、原研究台账 | 接入与隔离测试完成，真实运行待核验 |
| 缺失数据不能记零，权限不因连续成功自动扩大 | [评价与实操手册](maintenance-cycle-runbook.md) | 部分为程序检查，部分仍为人工执行规则 |

因此，“治理即代码”并不表示已经消除了人工治理。它表示把能明确表达的规则做成可执行检查，把尚未自动执行、尚未验证的部分也明确暴露出来。

## 下一步如何检验价值

研究主张是：在相同任务范围与错误后果边界下，保留足够证据并关联真实消费者，能否减少必要的人工接管，同时不增加下游错误？

后续需事前固定观察窗口和验收范围，记录成功、失败、等待、拒绝及人工介入，比较每100次同类维护机会的监督会话与分钟数，并同时报告原始样本量、错误、复发、漏报和总成本。未发生的消费者工作继续记未发生；没有完整人工记录和可比基线，就不计算节省比例。

反例同样有价值：记录成本增加却没有减少接管；错配证据被误放行；正常工作频繁被误拦；大输入总因预算耗尽而无法留证；恢复仍需要人反复定位。出现这些情况，应修改机制，而不是只展示空间收益。

本案例已经提供的是一条可追踪的工程路径：纠正保留假设、实施无损维护、拒绝无证据的完成声明、接入真实消费留证。学术价值有待可复现对照和更多独立案例支持；商业价值有待外部使用与付费验证。人的注意力是希望释放的资源，目前仍是待测结果。

### 证据与复现范围

生产数字及历史纠正可与[原案例最新补充](research-engine-db-rot.md)交叉核对；公开证据包复现的是声明评价结果，不能复现私有业务数据或替代原始回执认证。账户、订单、策略、服务器位置及私有链接均未公开。本文使用已有实践证据，不作首创或行业优越性结论。
